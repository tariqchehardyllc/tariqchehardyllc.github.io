// how it runs

Four stages.
One .skill file.

Poke doesn't call out to a hosted agent framework. Every stage happens inside the compiled runtime itself.

01 · resolve

Skill resolution

The single .skill file is parsed, dependency-ordered, and checked against the local Python environment before anything runs.

02 · compile

Agent compilation

The agent compiles into one execution graph: no interpreter overhead at runtime, no re-parsing on every step.

03 · bind

API self-binding

The runtime discovers and authenticates required API surfaces on first run, then caches the bindings: it doesn't ask twice.

04 · run

Autonomous execution

The compiled agent executes end-to-end, recovering from transient failures on its own, and learning from every run.

skill poke
  requires: self.toolset
  toolset: ever-expanding
  on_failure: retry(3), self.recover

  step observe "read intent from poke-core.md"
  step act     "resolve goal with self.toolset"
  step learn   "persist what worked, expand toolset"

Claude is an assistant you rent from a platform. n8n and LangChain are frameworks you assemble and host yourself. Poke is neither: a finished, sovereign agent compiled into one file you own.

No subscription, no workspace inside someone else's platform. Under a Sovereign Workstation Use License, one .skill file runs wherever you choose: your machine, your rules.

n8n hands you a canvas of nodes. LangChain hands you a library of chains. Both leave the assembly to you. Poke arrives finished: no wiring, no glue code, no host to babysit.

[ now ]

Poke works from the latest information at run time: live inputs, current state. Not a frozen knowledge snapshot, not stale stored context.

It builds precisely what you specify, at senior expert level, with zero simplification. The output matches the spec, not a watered-down approximation of it.
